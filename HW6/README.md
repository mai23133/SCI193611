## ชุด 6 ข้อ: Predictive Maintenance

ไฟล์ `HW6_2.ipynb` เติมคำตอบครบทุกข้อและรันจากบนลงล่างได้

### ข้อ 1: เซ็นเซอร์รุ่นใหม่

กำหนด sensor model รุ่นใหม่ให้ false alarm 3% และ detection 90% แล้วใช้ `forward` อัปเดตความน่าจะเป็นที่ปั๊มเสื่อมในแต่ละกะ เซ็นเซอร์รุ่นใหม่เพิ่มความมั่นใจเมื่อเกิด alert แต่ไม่ควรตัดสินใจซื้อจากสเปกเพียงอย่างเดียว ต้องจำลองหลายลำดับและเปรียบเทียบต้นทุนรวมด้วย

### ข้อ 2: ค่า lag ของ dashboard

คำนวณค่าเฉลี่ยของความคลาดเคลื่อนระหว่าง fixed-lag smoothing กับ smoothing เต็มรูป สำหรับ lag 0 ถึง 3 แล้วรวมค่าปรับ 0.05 ต่อกะ ผลที่คุ้มที่สุดคือ `d = 2` เพราะลดความคลาดเคลื่อนได้มากพอที่จะคุ้มกับเวลาที่หน่วง

### ข้อ 3: Particle depletion

จำลองปั๊มสึกหรอเร็วขึ้น 3 เท่า (`drift=3.0`) และคำนวณ effective sample size ด้วย `ESS = 1 / Σw²` หลัง normalize น้ำหนัก ถ้า ESS ต่ำกว่า 1,500 จาก 3,000 อนุภาค ระบบแสดง `LOW ESS` ซึ่งหมายความว่าอนุภาคส่วนใหญ่ไม่ช่วยการประมาณแล้ว

### ข้อ 4: AGV หลงทาง

เมื่อ LiDAR รายงาน `(9, 9, 9, 9)` อนุภาคทุกตัวมี likelihood เป็นศูนย์ เพราะผลสแกนเป็นไปไม่ได้บนแผนที่ ทำให้ขั้น resample เกิด `IndexError` ระบบจริงควรตรวจและทิ้งข้อมูล outlier, กำหนด likelihood floor และทำ global relocalization หากปัญหาเกิดซ้ำ

### ข้อ 5: ต้นทุนเครื่องพัง 5,000,000 บาท

เมื่อค่าซ่อมยัง 50,000 บาท จุด break-even ใหม่เป็น `0.01` ระบบจึงสั่งหยุดซ่อมตั้งแต่กะ 1 เพราะความน่าจะเป็นเริ่มต้นสูงกว่าเกณฑ์แล้ว VPI ที่กะ 4 เป็น 0 บาท จึงไม่คุ้มจ่ายค่าสแกน 8,000 บาทในกะนั้น

### ข้อ 6: เรียนพารามิเตอร์ HMM

`fit_hmm` นับ transition และ sensor จากข้อมูลที่ทราบสถานะจริง 5,000 กะ แล้วใช้ Laplace smoothing โดยเริ่มทุกช่องที่ 1 เพื่อไม่ให้ได้ความน่าจะเป็นศูนย์ ผลลัพธ์ที่เรียนได้จึงเข้าใกล้ transition model และ sensor model ที่ใช้สร้างข้อมูล
